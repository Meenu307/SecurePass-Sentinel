    ⚙️ Password Generator FAQs

    1. How does the password generator create random passwords?

    It utilizes cryptographically secure pseudorandom number generators (CSPRNG) via the Web Cryptography API (`crypto.getRandomValues`) to draw unpredictably from character sets, ensuring immunity against algorithmic replay attacks.

    2. Are generated passwords saved on any server?

    No. Passwords generated in the Generator module remain strictly ephemeral inside your browser's execution memory. They are never transmitted, logged, or retained.

    3. Why is character diversity important in generated passwords?

    Including numbers, symbols, and mixed cases expands the character pool (entropy). This makes automated guessing exponentially more difficult for cracking tools.

    4. What length should I choose for high security?

    We recommend a minimum length of 16 characters. A 16-character password with full character variety takes billions of years to brute-force with modern GPU clusters.

    🛡️ Security Checker FAQs

    1. What is a Brute Force Attack?

    A brute force attack is an automated method where attackers submit thousands or millions of password combinations per second until the correct one is guessed.

    2. What is a Dictionary Attack?

    A dictionary attack tests pre-compiled lists of standard vocabulary words, common phrases, or leaked password databases instead of random characters.

    3. How does the crack-time estimator work?

    It calculates password entropy in bits using the formula E = L * log2(R) (Length * log2(Character Pool)), then models a cracking rig performing 100 billion guesses per second to project realistic cracking duration.

    4. Why should I avoid reusing passwords across multiple sites?

    If one website gets hacked in a data breach, attackers attempt those leaked credentials on hundreds of other popular platforms in automated Credential Stuffing attacks.
